# 1. 프로젝트 개요

## 1.1 서비스 정의

FuelRoute는 장거리 이동 중 운전자의 현재 연료 상태와 목적지까지의 이동 경로를 바탕으로, **현재 연료로 안전하게 접근할 수 있는 주유소를 찾고 가격과 우회 비용을 비교하여 주유 지점을 추천하는 Agent 기반 플래너**다.

## 1.2 프로젝트 배경

기존 주유소 검색은 위치나 리터당 가격을 중심으로 정보를 제공한다.

하지만 실제 장거리 주유 의사결정에는 다음 요소가 동시에 필요하다.

- 계기판에 표시된 주행 가능 거리(km)
- 안전하게 남길 여유 거리(km)
- 목적지까지의 실제 경로
- 경로 주변 주유소
- 후보 주유소 가격
- 주유소를 들르기 위해 필요한 추가 거리와 시간

따라서 “가장 싼 주유소”가 아니라 **현재 차량 상태로 실제 도달 가능하면서 경로 이탈 비용까지 고려했을 때 합리적인 주유소**를 찾는 것이 문제다.

## 1.3 해결하려는 문제

사용자가 직접 여러 앱과 정보를 비교하지 않고 다음 질문에 답할 수 있게 한다.

> “현재 이 정도 연료가 남았는데, 목적지로 가는 길에 어디까지 안전하게 갈 수 있고 그 범위에서 어느 주유소에 가는 것이 가장 합리적인가?”

## 1.4 서비스 목표

1. 사용자의 연료 조건을 이용해 안전 주행 가능 범위를 계산한다.
2. 목적지 경로에서 도달 가능한 주유소 후보를 찾는다.
3. 가격과 우회 거리·시간을 실제 데이터로 비교한다.
4. 조건을 충족하지 못하는 후보의 제외 사유를 설명한다.
5. 적합한 후보가 없으면 검색 범위나 후보를 재구성한다.
6. 판단 과정과 근거를 실행 로그로 추적 가능하게 만든다.

## 1.5 도메인 선택 이유

연료에 따른 도달 가능성이라는 명확한 제약, 실제 주유소·경로 데이터, 후보 부족 시 재계획, 저장 가능한 주유 계획이 하나의 흐름으로 연결되어 FuelRoute를 선택했다. 초기에는 반려동물 외출·혼잡 회피·EV 충전·섬유 안전/수출·국제유가 서비스를 검토했으나, 현재 범위는 장거리 주유 의사결정에 집중한다.

# 2. 타깃 사용자

## 2.1 핵심 사용자

MVP 기준:

- 자가용으로 중·장거리 이동하는 운전자
- 주유비에 민감한 운전자
- 주유 때문에 큰 우회를 하고 싶지 않은 운전자
- 이동 중 주유 시점을 결정하기 어려운 운전자

## 2.2 문제 상황

예:

> 대구에서 서울까지 이동 중이다.  
> 휘발유 차량이며 계기판 주행 가능 거리는 180km다.
> 안전 여유로 30km는 남기고 싶다.
> 목적지 방향으로 가면서 10분 이상 우회하지 않는 주유소 중 합리적인 곳을 찾고 싶다.

## 2.3 기존 해결 방식과 한계

기존 방식:

- 현재 위치 주변 최저가 주유소 검색
- 내비게이션에서 경로 주변 주유소 탐색
- 운전자가 직접 가격과 거리 비교

한계:

- 현재 연료로 후보까지 실제 도달 가능한지 별도 판단 필요
- 리터당 가격과 우회 비용을 함께 비교하기 어려움
- 장거리 경로 전체에서 “주유해야 할 구간”을 자동으로 계산하지 않음
- 조건을 만족하지 못했을 때 자동 재계획하지 않음

# 3. 핵심 가치 및 차별성

## 3.1 핵심 가치

> **주유소 검색이 아니라 주유 의사결정을 지원한다.**

추천 전에 안전한 도달 가능성을 먼저 판정하고, 그다음 사용자 조건과 경제성을 비교한다.

## 3.2 차별화 방향

### 확정된 방향

- 계기판 주행 가능 거리(km)를 기본 입력으로 사용하며 L/연비는 요구하지 않음
- 안전 여유 거리(km)를 차감해 접근 가능한 범위를 제한
- 목적지의 실제 경로를 기준으로 주유소를 탐색
- 최저가만으로 추천하지 않음
- 조건을 만족하지 않으면 재계획

### 검증되지 않은 차별성

시장에 동일한 기능 조합이 존재하지 않는다는 경쟁 서비스 조사는 아직 수행하지 않았다.

따라서 현재 문서에서는 “시장 최초”, “유일한 서비스”와 같은 표현을 사용하지 않는다.

# 4. 사용자 시나리오

## 4.1 정상 시나리오

1. 사용자가 출발지와 목적지를 입력한다.
2. 주행 가능 거리(km), 남길 안전 여유(km), 유종을 입력한다.
3. 선택적으로 최대 허용 우회시간을 입력한다.
4. 시스템이 목적지까지의 경로를 확인한다.
5. 안전하게 이동 가능한 경로 구간을 계산한다.
6. 해당 구간의 주유소 후보를 찾는다.
7. 후보별 가격과 실제 경유 시 우회시간을 비교한다.
8. 조건을 만족하는 후보를 추천한다.
9. 사용자는 추천 근거와 제외된 후보의 사유를 확인한다.
10. 필요하면 주유 계획을 저장한다.

## 4.2 재계획 시나리오

가장 저렴한 후보가 최대 허용 우회시간을 초과한다.

1. 해당 후보를 제외한다.
2. 이미 확보한 다른 후보를 재평가한다.
3. 후보가 부족하면 새로운 검색 지점을 추가한다.
4. 재계획 횟수 상한에 도달하지 않는 범위에서 대안을 찾는다.

## 4.3 조건 부족 시나리오

사용자:

> “서울 가는 길에 싼 곳에서 넣고 싶어.”

주행 가능 거리 또는 안전 여유(km)가 없으면 해당 값만 추가로 받는다. km 방식에서는 L 연료량이나 연비를 요구하지 않는다.

시스템은 값을 임의로 생성하지 않고 필요한 조건을 되묻는다.

## 4.4 Tool 실패 시나리오

주유소 상세조회 일부가 실패한 경우:

- 실패 사유를 기록한다.
- 다른 후보가 있다면 계속 평가한다.
- 핵심 판단에 필요한 데이터가 부족하면 판단 불가 상태를 사용자에게 안내한다.

## 4.5 Tool이 필요 없는 시나리오

사용자:

> “이 서비스는 어떤 기준으로 추천해?”

외부 API를 호출하지 않고 서비스 기준을 설명한다.

## FR-001 — 주행 조건 입력 및 요청 분석

- **목적:** 추천에 필요한 사용자 조건을 확보한다.
- **상세 동작:** 출발지, 목적지, 유종, 계기판 주행 가능 거리·안전 여유(km) 및 선택 제약을 추출한다. 기존 L/연비 입력은 호환 지원한다.
- **입력 데이터:** 사용자 자연어 또는 UI 입력
- **출력 데이터:** 구조화된 주행 조건
- **예외 상황:** 필수값이 누락된 경우 임의값을 사용하지 않고 사용자에게 추가 입력 요청
- **우선순위:** Must
- **상태:** 확정
- **원본 요구사항:** F3005, F3006, F3010
- **Acceptance Criteria:**
  - [x] 요청에 없는 연료량/연비를 자동 생성하지 않는다.
  - [x] 주행 가능 거리·안전 여유(km)를 사용자에게 받고 L 연료량·연비를 필수로 요구하지 않는다.
  - [x] 후속 요청에서 변경한 조건만 갱신한다. 같은 세션 ID의 검증 조건/요약을 이어받고 무효 새 값은 다시 확인한다.
  - [x] 누락 필수값 목록을 식별할 수 있다.

F3005는 요청 분석·위치 해석 그래프와 CLI에서 구현·검증했다. 모델이 낸 값을 원문 구절·숫자·단위·날짜와 대조하고 미확인 값은 채택하지 않는다. 지명·주소만 있으면 Kakao Local로 좌표를 조회하고 유일한 결과만 자동 확정한다. 여러 후보나 결과 없음은 상세 위치를 다시 묻는다. 입력 좌표는 유지하고 API 좌표의 출처·지역 수준 여부를 표시한다. [분석 기록](DEVELOPMENT.md#f3005-implementation), [위치 해석 기록](DEVELOPMENT.md#f3005-geocoding)을 따른다.

F3006은 준비된 추천 입력만 GMS에 작업 순서를 제안받고 누락·중복·의존 순서를 코드로 검증해 실행 전 계획으로 보관한다. 인사·설명과 미준비 입력은 계획 모델을 생략한다. 모델이 주행 조건·안전 잔량·호출 상한을 바꾸지 못하며 계산·판정·정렬은 일반 코드 작업으로 구분한다. 작업 계획 생성은 실제 조회·추천 성공을 뜻하지 않는다. F3007은 계획에 따른 실제 조회와 결과 통합을 한 회차 연결했다. F3009에서 상한 있는 그래프 재계획을 연결했다. 대화 맥락(F3010)은 같은 세션의 검증 조건/요약을 SQLite로 이어받으며 최종 문장은 후속이다. [계획 구현·검증 기록](DEVELOPMENT.md#f3006-implementation)을 따른다.

F3010은 현재 원문의 값/단위/근거만 추출한 뒤 미언급 값만 같은 세션의 맥락에서 병합한다. 지명·좌표·입력 방식이 바뀌면 관련된 이전 값은 지우고 통합 조건을 다시 검증한다. 인사/설명은 기존 여행을 보존하며 명시 초기화/조건 제거는 해당 원문을 검사한다. SQLite에는 최신 조건·오류/보완 대상·짧은 요약만 보관하고 원본 Tool/전체 대화·가격·경로·실행 캐시는 보관하지 않는다. 후속 추천은 새로 조회한다. 세션 분리·저장 버전 충돌/손상을 검증했다. [구현·검증](DEVELOPMENT.md#f3010-memory)을 따른다.

## FR-002 — 기본 이동 경로 조회

- **목적:** 목적지까지의 실제 자동차 이동 경로와 거리·시간을 확보한다.
- **상세 동작:** 외부 길찾기 API를 사용해 기본 경로를 조회한다.
- **입력 데이터:** 출발 좌표, 목적 좌표
- **출력 데이터:** 총거리, 소요시간, 경로 정보
- **예외 상황:** 경로 없음, 잘못된 좌표, API 실패
- **우선순위:** Must
- **상태:** 검증 필요
- **원본 요구사항:** F3001, F3007 — FuelRoute의 경로 조회 Tool과 결과 통합에 대응. 원본 F3004는 휴게소 보조정보에 대응한다.
- **Acceptance Criteria:**
  - [x] 실제 API 호출로 거리와 시간이 반환된다.
  - [x] 상세 경로를 이용해 경로상 검색 위치를 계산할 수 있음을 검증한다.

## FR-003 — 안전 주행 가능 거리 계산

- **목적:** 사용자가 안전하게 접근 가능한 최대 탐색 범위를 계산한다.
- **상세 동작:**

```text
안전 주행 가능 거리(km) = 주행 가능 거리(km) - 안전 여유 거리(km)
예: 180km - 30km = 150km
```

- **입력 데이터:** 주행 가능 거리(km), 안전 여유(km). 연비 없이 계산하며 기존 L 방식도 별도로 지원한다.
- **출력 데이터:** 안전 주행 가능 거리(km)
- **예외 상황:** 주행 가능 거리0 이하, 음수·같거나 큰 안전 여유, 비유한 값, 필수값 누락, km와 L 연료량 혼용
- **우선순위:** Must
- **상태:** 확정
- **원본 요구사항:** F3008
- **Acceptance Criteria:**
  - [x] 계산은 LLM이 아닌 일반 코드에서 수행한다.

- **우선순위:** Must
- **상태:** 확정
- **원본 요구사항:** F3009
- **Acceptance Criteria:**
  - [x] 동일 결과를 얻을 호출을 불필요하게 반복하지 않는다.

FR-003/007/008의 체크는 추천·재계획 Python 서비스와 CLI 기준이다. [추천 검증 기록](verification/2026-11-18-recommendation.json)에 실제 성공, 기존 비용의 로컬 재판정, 모의 재계획 검증을 구분했다. F3009에서 분석·계획·조회·판정·재계획을 그래프에 연결했다. F3010 조건 맥락은 연결했고 최종 문장·HTTP·화면은 후속 단계다.

F3008은 그래프의 별도 판정 노드에서 실제 경로 비용을 재계산하고 항목별 통과/불충족/미확인 근거를 반환한다. 도착 상한은 출발 시각·명시 날짜·주유/정차 예상 분을 기준으로 비교하며 날짜·정차시간을 임의 채우지 않는다. 시간 제약으로 확정 후보가 바뀌면 보조정보도 해당 후보에만 연결한다. 계산·판정은 추가LLM/API 없이 수행하며 기존 실제 비용 재판정과 새 GMS 시간 필드 추출 검증을 구분했다. [F3008 기록](DEVELOPMENT.md#f3008-judgement)을 따른다.

F3009는 최초 실행과 추가 회차를 분리하고 요청별 실제 경로·상세·검색 캐시를 유지한다. 미평가 후보를 먼저 사용하고 없을 때 안전 구간의 새 검색점 한 곳만 추가한다. 입력 부족·핵심 실패·확정 추천·평가/회차 상한은 추가 호출 전에 검사하며 회차·종료 이유·다음 입력 안내를 반환한다. 재계획에 모델을 추가 호출하거나 안전/시간 제약을 완화하지 않는다. 실제 후보9곳/추가2회 상한 종료와 모의 성공/실패 검증을 구분했다. [구현·검증 기록](DEVELOPMENT.md#f3009-replanning)을 따른다.

## NFR-003 — 성능

- 대표 요청의 전체 처리시간을 기록한다.
- 현재 원본 요구사항에는 구체적인 초 단위 기준이 없으므로 임의 SLA를 확정하지 않는다.
- **원본:** NF3005

## NFR-004 — 구조

- Frontend/Backend를 분리한다.
- Agent와 Tool 로직을 모듈로 분리한다.
- **원본:** NF3006

## NFR-005 — 외부 데이터 준수

- 사용 API의 출처, 호출한도, 이용조건을 기록한다.
- **원본:** NF3007

## NFR-006 — 데이터 정확도 및 안전

- 주행 가능 거리는 사용자가 읽은 계기판 값과 안전 여유를 기반으로 한 **추정치**임을 표시한다. 기존 L/연비 방식도 사용자 입력에 따른 추정치다.
- 실제 주행 가능 거리는 교통, 경사, 차량상태, 운전습관 등에 따라 달라질 수 있다.
- 서비스가 차량 계기판이나 제조사 데이터를 직접 확인한다고 오해하게 만들지 않는다.

## NFR-007 — 함수 설명과 독립 실행

- 새로 작성하거나 수정하는 모든 함수에 목적·호출 시점·입력·출력·실패·부작용·사용 예시를 설명하는 docstring을 작성한다.
- Agent Tool은 상세 `description`과 입력 필드 설명을 실제 Tool 스키마에 등록한다. 함수 이름만으로 사용법을 추정하게 하지 않는다.
- 성공과 실패는 동일한 `ToolResult` 필드 구조로 반환한다.
- 후보 조회·상세 정보·보조 정보 검색 TODO는 Agent 전체 실행 없이 각각 호출하고 결과를 확인할 수 있어야 한다.
- 구체적인 설명 템플릿과 응답 계약은 [`ARCHITECTURE.md`](ARCHITECTURE.md) 14장에서 관리한다.

## NFR-008 — GMS LLM 사용

- LLM 호출은 GMS를 사용하고, 모델명·호출 주소·키는 환경변수로 분리한다.
- GMS 제공 모델 중 요청 분석, 도구 호출, 구조화 출력 검증을 통과한 모델을 사용한다.
- LLM 호출과 외부 데이터 API 3종 호출을 각각 검증한다.
- 안전거리·우회비용·제약 판정과 로그 저장은 일반 코드로 수행한다.

# 7. MVP 범위

## 7.1 1차 개발 필수

- FR-001 ~ FR-013
- 원본 프로젝트의 필수 기능 F3001 ~ F3019
- 외부 API 3종 이상이라는 프로젝트 조건 충족
- 대표 시나리오 최소 5개 검증

## 7.2 추후 검토

- 실제 주유량 최적화
- 차량 OBD-II 또는 제조사 데이터 연동
- 사용자의 선호 브랜드/시설 고도화
- 실시간 교통정보 별도 Tool
- 시설 선호에 따른 휴게소 추천 고도화 — 기본 보조정보 조회·표시는 FR-013으로 MVP에 포함
- 심화 F3020 ~ F3023

## 7.3 현재 범위에서 제외

- 미래 국내 유가 예측
- 주유소 결제/예약
- 실시간 차량 센서 자동 수집
- 턴바이턴 내비게이션
- 전기차 충전소 추천
- 주유소 대기열 예측

미래 유가 예측은 국제유가만으로 국내 소매가격을 설명하기 어렵고 예측 모델 검증 부담이 커서 제외한다. 차량 자동 수집은 제조사 API·OBD 연동으로 범위가 확대되므로 MVP에서는 직접 입력을 사용한다. 두 기능은 각각 검증 가능한 예측 데이터·모델 확보, 핵심 MVP 완성 후 차량 연동 단계에서 재검토한다.

# 8. 성공 기준

MVP 완료 판단 기준:

1. 필수 기능 F3001 ~ F3019가 실제로 동작한다.
2. 현재 연료 조건 때문에 최저가 주유소가 제외되는 테스트가 통과한다.
3. 우회시간 조건 때문에 최저가 주유소가 제외되는 테스트가 통과한다.
4. 후보 부족 시 재계획이 실제 발생하고 상한에서 종료된다.
5. Tool 하나 실패해도 가능한 다른 후보 처리가 진행된다.
6. 후속 요청에서 변경된 조건만 갱신된다.
7. 추천 결과와 실행 로그의 근거가 일치한다.
8. API 키가 코드·UI에 노출되지 않는다.
9. 계획 CRUD와 로그 조회/삭제가 동작한다.
10. 대표 시나리오별 기대/실제 차이를 기록한다.
11. GMS LLM과 외부 데이터 API 3종의 실제 호출을 각각 확인하고, 세 필수 조회 TODO를 독립 호출할 수 있다.
12. 휴게소 보조정보의 출처·기준일·매칭 상태를 표시하고, 보조 API 실패를 핵심 추천 실패와 구분한다.
