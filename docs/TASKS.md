## 필수 기능 완료 후 — 선택 심화·추가 작업(11월 20일 이내 여유가 있을 때)

아래는 PDF의 선택 과제와 추가 작업이다. **필수 완료 체크에 포함하지 않으며**, 필수 구현·검증을 마친 뒤 11월 20일 안에 가능한 항목만 선택한다. 이 작업 때문에 필수 일정을 늦추거나 개발 종료일을 연장하지 않는다. 선택하지 않은 항목은 미선택으로 남긴다.

- [ ] **심화 선택 여부 결정:** F3001~F3019가 모두 동작한 뒤 범위·시간·이전 Vector DB 보유 여부에 따라 채택할 F3020~F3023을 명시한다(p.20).
- [ ] **F3020 — 이상 징후 판단(선택 시):** 규칙으로 반복 호출·과다 재계획·계획 불일치를 판정하고 근거가 없으면 판정 불가로 둔다. 이상 실행에만 LLM 원인 진단을 붙이며 진단 실패가 판정/로그를 손상시키지 않게 한다(p.20~21·25).
- [ ] **F3021 — Planner·Worker 구조 전환(선택 시):** 작업 목록/수행 결과 메시지를 정의하고 로깅의 검증 결과를 재계획에 반영한다. Worker는 고칠 여지가 있는 실패에만 LLM으로 재시도/건너뜀/계획 변경을 판단하고 고정 인자·동일 Tool·재시도 상한을 지킨다. 정상·치명적 실패·필수 인자 누락에는 LLM을 쓰지 않는다. 전환 전후 및 Worker LLM on/off의 재계획 수·요청당 LLM 호출 수·응답시간을 비교한다(p.21~22·25).
- [ ] **F3022 — RAG 검색 Tool(선택 시):** 2회차 Vector DB 검색을 연결해 외부 API로 확인할 수 없는 질문에 근거 문서·출처를 반환한다. 색인이 없으면 `NO_INDEX` 등 정의된 응답을 사용한다(p.22·25).
- [ ] **F3023 — 캘린더 연동 Tool(선택 시):** 일정 조회/등록 계약과 로컬 저장소 구현을 먼저 확인하고 Google Calendar 구현으로 교체 가능하게 한다. 등록은 계획 ID만 받아 제목·시각을 저장소에서 읽고 조회한 일정을 제약 판단에 반영한다(p.22~23·25).
- [ ] **추가 공개 배포(선택):** Backend HTTPS·환경변수·CORS를 설정하고 기존 Netlify 프론트에서 추천·CRUD·로그·상태를 확인한다. PDF의 필수 제출은 GitLab 업로드와 재현 가능한 실행이며 공개 Backend 도메인을 필수라고 추가하지 않는다.
