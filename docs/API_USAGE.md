# 외부 API 호출 한도와 공개 이용조건

2026-11-18 계정 확인값과 2026-11-19 Kakao Local·GMS 작업 계획 추가 검증을 기록한다. 공개 문서 조사와 사용자 제공 계정 정보를 구분한다. 공식 공개 문서는 2026-11-20에 다시 확인했다. 이 기록은 개별 계약이나 상용 서비스에 대한 승인 자체를 뜻하지 않는다.

## 2026-11-20 공식 문서 재확인

- Opinet 공식 일반 API 안내는 일반 API 300call/일과 1,500call/일 희망 시 제휴 필요를 계속
  안내한다. 현재 계정의 300회/일과 일치하지만 제휴·상업 이용 승인을 뜻하지 않는다.
- Kakao Developers 쿼터 문서는 앱별 현재 쿼터를 앱 관리 화면에서 확인하도록 안내하고 공개
  제공량은 변경될 수 있다고 명시한다. 따라서 사용자가 확인한 Mobility 10,000회/일을 계정
  확인값으로 유지하고 Kakao Local의 미확인 수치로 복사하지 않는다.
- Kakao Mobility 자동차 길찾기 공식 명세의 요청 주소는 현재 구현과 같은
  `https://apis-navi.kakaomobility.com/v1/directions`이며 REST API 키 인증을 요구한다.
- 전국휴게소정보표준데이터 공식 상세는 국토교통부 소관·한국도로공사 제공, 반기 갱신,
  개발계정 신청 가능 트래픽 10,000, 요청당 `numOfRows` 최대1,000과 현재 구현 Endpoint를
  안내한다. 데이터 기준일과 포털의 개별 이용허락범위를 계속 확인해야 한다.

## Opinet

- 일반 API는 무료 조회 범위로 안내되며, 더 높은 일반 API 호출량은 제휴 절차가 별도로 안내되어 있다. 현재 계정에는 기본 300회/일을 적용한다.
- 공식 페이지의 저작권정책은 자료 이용 시 권리와 출처를 확인하도록 하며 수익을 얻는 이용에는 사전 협의·허락을 안내한다. 일반 키 발급을 무제한 재배포나 상업 이용 허가로 해석하지 않는다.
- 개발에서는 명시적 검색점과 후보 수를 제한하고 필요한 후보만 상세 조회한다. 원본 가격·기준시각을 보존하며 제공하지 않은 실시간 가격을 생성하지 않는다.

근거: [API 안내 및 페이지 내 저작권정책](https://www.opinet.co.kr/user/custapi/custApiInfo.do).

## Kakao Mobility 자동차 길찾기

- 앱에 적용된 자동차 길찾기 한도를 사용한다. 다중 출발지·목적지 등 다른 API에 같은 한도를 적용하지 않는다.
- 운영정책의 쿼터 및 제한 항목은 API별 요청수를 별도 가이드에 따르도록 한다. 현재 앱의 유료 API 설정·추가 계약·초과 과금 승인을 추정하지 않는다.
- 서비스 약관에는 취득 정보의 복제·제공 등에 관한 제한이 있다. API 응답을 독립 데이터 상품이나 공개 원본 데이터베이스로 재배포할 권한을 얻었다고 해석하지 않는다.
- 개발에서는 동일 옵션의 기본·접근·경유 요청을 제한된 횟수로 실행한다. 일시적 경로 계산에는 원본 좌표를 사용하고, 개발 기록에는 필요한 거리·시간·요약만 남긴다.

근거: [쿼터](https://developers.kakao.com/docs/ko/getting-started/quota), [운영정책 제6조](https://developers.kakao.com/terms/ko/site-policies), [서비스 약관](https://developers.kakao.com/terms/ko/site-terms), [자동차 길찾기 명세](https://developers.kakaomobility.com/guide/navi-api/directions.html).

## Kakao Local 주소·장소 검색 — 입력 위치 해석

- 주소 검색 `https://dapi.kakao.com/v2/local/search/address.json`을 먼저 호출하고 0건일 때만 `https://dapi.kakao.com/v2/local/search/keyword.json`을 호출한다. 기존 `KAKAO_REST_API_KEY`를 사용하며 해당 앱의 카카오맵 활성화가 필요하다.
- 현재 앱은 초기 403/비활성 응답 후 사용자가 활성화했다고 확인했고, 대구·서울 검색의 정상 응답을 확인했다. 자동차 길찾기 10,000회/일을 Local 한도로 옮겨 적지 않는다. 실제 앱 무료 쿼터 적용과 주소/장소 검색 한도 수치는 콘솔 확인 전이다.
- 코드 상한은 위치당 최대 2회, 요청당 출발/목적 최대 4회다. 첫 페이지 5건만 요청하며 전체 결과가 여러 개면 자동 선택하지 않는다. 동일 실행의 동일 지명은 재사용하고 실패한 요청을 자동 재시도하지 않는다. HTTP 400의 제공사 code=-10도 호출 한도 오류로 분류한다.
- `analyze`는 GMS 1회와 필요할 때 위 위치 검색만 수행한다. `recommend`·`route-spike`의 기존 호출 예산과 별도이며, 현재 자동으로 길찾기·주유소 조회를 이어서 실행하지 않는다.
- `plan`은 분석 GMS 1회에 준비된 추천 요청만 계획 GMS 1회를 추가한다. Local 검색 상한은 동일하며 길찾기·Opinet·휴게소 조회 실행은 없다. 실제 정상/누락/인사 CLI 검증은 명시적 좌표로 GMS 총 4회, Local 0회였다. 계측 사전 실행에서 분석·계획 2회를 더 사용했으며 [검증 JSON](verification/2026-11-19-task-plan.json)에 구분했다.

근거: [주소/장소 API](https://developers.kakao.com/docs/ko/local/dev-guide), [카카오맵 활성화·이용 정책](https://developers.kakao.com/docs/ko/kakaomap/common), [실제 검증](verification/2026-11-19-geocoding.json).

## 전국휴게소정보표준데이터

- 데이터 상세는 무료 제공과 이용허락범위 안내 링크를 제공한다. 포털 정책은 제3자 권리와 개별 데이터에 부착된 이용허락 조건을 확인하도록 안내한다.
- 이번에 확인한 공개 응답만으로 특정 공공누리 유형이나 무제한 상업 이용 허가를 확정하지 않는다. 공개 서비스의 재배포 범위를 확대할 때 상세의 이용허락 표시를 다시 확인한다.
- 개발에서는 제공기관·데이터 기준일을 보존하고, 같은 휴게소·주유소 또는 실시간 시설 상태라는 확인되지 않은 사실을 추가하지 않는다. 현재 개발계정의 일일 한도와 활용기간을 따른다.

근거: [데이터 상세](https://www.data.go.kr/data/15025446/standard.do), [포털 이용허락범위 및 이용약관](https://www.data.go.kr/ugs/selectPortalPolicyView.do).

## 현재 코드에 적용한 호출 범위

2026-11-19 km 기본 입력 전환은 API의 인증/쿼터를 바꾸지 않는다. 실제 km 완전 입력과 안전 여유 누락을 확인한 GMS는 총3회이며 명시적 좌표를 사용해 외부 데이터 API는 호출하지 않았다. [km 입력 검증](verification/2026-11-19-distance-input.json)에 기존 F3006 검증6회와 구분했다. 계산 Tool의 km 스키마/실행과 기존 실행기의 검색 경계는 오프라인으로 검증했다.

`route-spike` 기본값은 검색점 최대 3개와 평가 후보 최대 3개다.

| 제공사 | 한 번의 실험에서 최대 호출 수 | 구성 |
|---|---:|---|
| Opinet | 6회 | 후보 검색 3회 + 상세 조회 3회 |
| Kakao | 7회 | 기본 1회 + 접근 3회 + 경유 3회 |
| GMS | 0회 | 명시적 조건과 일반 Python 계산만 사용 |

설정된 `max_candidates`가 N이면 Opinet 상한은 검색점 수+N, Kakao 상한은 1+2N이다. 인증·설정·한도 오류는 즉시 중단하며 자동 재시도하지 않는다. 실제 호출 수는 결과의 `api_call_counts`와 개별 호출 메타에 기록한다.

`recommend`는 재계획 최대 2회·회차당 최대 3곳·전체 최대 9곳 평가가 기본값이다. 미평가 후보를 먼저 재사용하고, 없을 때만 회차당 검색점 한 곳을 추가한다.

| 제공사 | 기본 추천 한 번의 최대 호출 수 | 구성 |
|---|---:|---|
| Opinet | 14회 | 최초 검색 3회 + 추가 검색 최대 2회 + 상세 최대 9회 |
| Kakao | 19회 | 기본 1회 + 접근/경유 최대 18회 |
| GMS | 0회 | 명시적 조건과 일반 Python 계산만 사용 |

검색/평가 설정을 늘리면 예산도 증가한다. 전체 평가 수를 E, 최초 검색점 수를 P, 재계획 상한을 R이라 하면 Opinet은 최대 P+R+E, Kakao는 최대 1+2E다. 캐시·조기 제외·추천 발견으로 실제 호출은 줄어들 수 있다. 동일 실행의 경로·상세·검색 캐시는 호출 종료 시 폐기한다. 이번 추천 실호출에서는 Opinet 6회·Kakao 7회를 사용했고 최초 회차에서 종료했다. [추천 검증 기록](verification/2026-11-18-recommendation.json)

이 상한은 실행 한 번의 요청 예산이다. 여러 프로세스·사용자의 공유 일일 한도 집계는 아직 구현하지 않았다. 전체 경로를 빠짐없이 검색하거나 모든 후보의 최저가를 보장하는 단계도 아니다.

## `run` — F3007~F3011 실행·판정·유한 재계획·최종 응답

`run`은 자연어 분석·위치 해석·계획 뒤 최초 회차와 필요할 때 최대2추가회차를 실행한다. `recommend`의 재계획 반복기를 중첩 호출하지 않고 요청별 세션의 결과·캐시를 재사용한다. 보완 입력/비추천이면 실행 Tool 호출은0회이며 계획 GMS도 생략한다. 동일 요청의 같은 경로만 캐시하고 종료 시 폐기한다.

| 제공사 | 기본 전체 실행 상한 | 구성 |
|---|---:|---|
| GMS | 3회 | 분석1 + 준비된 추천의 계획1 + 추천/미발견 최종 문단 구성1 |
| Kakao Local | 4회 | 입력 위치당 주소1 + 필요 시 장소1, 명시적 좌표는0 |
| Opinet | 14회 | 최초 검색3 + 추가 검색최대2 + 전체 상세최대9 |
| Kakao Mobility | 19회 | 기본1 + 전체 후보 접근/경유최대18 |
| 휴게소 | 1논리조회 / 최대10 HTTP | 추천 후보 주변만, 페이지당1000건·최대10페이지 |

한 회차 선택 수는 `min(max_candidates, 남은 전체 평가 예산)`이다. 최초 검색점P·추가 회차R·전체 평가E이면 Opinet은최대P+R+E, Mobility는1+2E다. 최초만 종료하면 기존6/7회 상한이다. GMS가 예산을 바꾸지 못하며 재계획에도 추가 모델 호출은 없다. 최종 GMS는 검증 문장의 ID 문단 구성만 수행한다. 입력 보완·인사·핵심 오류는 이 호출도 생략한다. 캐시·조기 제외·추천 발견으로 줄 수 있고 동일 실패 요청은 재시도하지 않는다. 휴게소0건/실패는 추천을 유지한다.

`data.execution.tool_call_counts`는 공통 Tool 시도 수이며 HTTP 계수가 아니다. 설정 누락은 HTTP 전에 실패하고 휴게소는 여러 페이지를 요청할 수 있다. 별도 계측한 실제 검증은 GMS2·Local0·Opinet6·길찾기7·휴게소1회였다. 실제 요청·시각·소요시간·정제된 결과는 [F3007 검증](verification/2026-11-19-tool-execution.json)에 있다.

## F3008 제약 판정

`run`의 판정 노드는 기존 경로·상세 응답과 사용자 조건을 일반 코드로 비교하므로 추가 GMS/데이터 API를 호출하지 않는다. 기본 GMS 상한은 분석1회+계획1회로 유지한다. 휴게소 조회는 판정 뒤 확정 후보에만 수행하며 전체 제외/미확인이면 생략한다. 도착 날짜·정차시간은 입력이며 API가 제공한 주유 대기/미래 교통 정보로 해석하지 않는다.

새 도착 날짜/정차시간 추출 검증에 실제 GMS1회를 사용했다. 경로·가격은 커밋된 F3007 응답을 로컬 재판정했고 새로운 길찾기/Opinet/휴게소/Local 호출은0회다. [F3008 근거](verification/2026-11-19-constraint-judgement.json)에 source 파일/커밋/SHA256과 추출·재판정 결과를 구분했다.


## F3009 재계획 실호출 검증

신규27개·전체319개 테스트로 후보 재사용·검색점 추가 성공, 추가0/1/2회, 전체 평가 예산, 개별 실패·핵심 중단·입력 보완·캐시 격리를 확인했다. 모의 응답과 실제 API를 구분한다.

실제 검증은 명시 좌표의 대구→서울·180km/안전 여유36km에1분 도착 상한을 주었다. 최초3곳과 추가2회/6곳을 포함해9곳에서 멈췄으며 종료 사유는evaluation_budget_exhausted였다. 실제 GMS2·Mobility19·Opinet12(검색3+상세9)회, Local·휴게소0회, 총처리 약24.5초였다. 재계획을 위해 GMS를 추가 호출하지 않았다. 새 검색점/추천 성공 분기는 모의 검증이며 실제 성공으로 기록하지 않는다. [정제 근거 JSON](verification/2026-11-19-graph-replanning.json)에 요청·모델·처리시각·소요시간·공통 결과·회차·실제 HTTP 계수를 남겼다. 다중 요청의 공유 일일 한도 집계는 여전히 후속이다.


## F3010 세션 조건 맥락

세션 ID가 있으면 검증 조건·짧은 요약을 모델에 참고 데이터로 전달한다. 요약/병합/저장에 추가 GMS를 쓰지 않으며 기존 분석1회·계획 추가1회의 상한은 같다. 같은 좌표는 조건 맥락에서 이어받아 Local 호출을 줄일 수 있다. 지명이 바뀌면 이전 좌표를 지우고 새 지명을 해석한다. 가격·경로·이전 요청의 실행 캐시는 장기 맥락으로 재사용하지 않으며 각 run에서 현재 응답을 조회한다.

실제 검증은 GMS4회·데이터API0회였다. 명시 좌표/180km/여유30km의 첫 요청, 같은 세션의 우회10분 변경, 여유50km 변경, 다른 세션의 부분 요청을 각각 분석했다. 저장 버전은 같은 세션1→2→3, 다른 세션1이었고 후자는 이전 위치/연료를 받지 않았다. 총처리 약10.0초이며 실제 숫자는 [근거 JSON](verification/2026-11-19-conversation-memory.json)에 있다. 이는 분석·SQLite 맥락 검증이며 새 실제 가격/추천 성공 검증으로 합치지 않는다. 전체 두 턴의 재조회는 모의 HTTP로 확인했다.

## F3011 최종 응답 실호출 검증

정렬 선호까지 명시한 대구 좌표→서울 좌표 요청에서 실제 GMS3·Mobility7·Opinet6·휴게소1회로 정상 추천과 근거 기반 한국어 응답을 확인했다. GMS는 분석·계획 뒤 검증 사실 ID의 문단 구성에 1회 사용됐다. 별도의 선호 미확인/안전 여유 누락/인사 요청은 분석 GMS만 1회씩 사용하고 데이터 API와 최종 모델을 생략했다. 커밋된 F3009 실제 비용의 추천 미발견 응답은 새 데이터 API 없이 최종 GMS1회만 호출했다. 이 검증 묶음의 합계는 GMS7·Mobility7·Opinet6·휴게소1회이며 한 요청의 상한과 혼동하지 않는다. [정제 근거 JSON](verification/2026-11-19-final-response.json)에 사례별 호출 수를 분리했다.
